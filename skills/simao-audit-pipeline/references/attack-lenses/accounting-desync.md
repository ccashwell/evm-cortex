# Lens 1 — Accounting Desync

You own the single largest class of 0xSimao's High findings: **a tracked total that no longer equals the thing it claims to track.**

Other lenses own math, ordering, and access. You own the gap between what the protocol *records* and what it *holds*.

## The shape

Value moves. A variable is supposed to move with it. It does not — or it moves in one branch and not the other, or it is written before the math that depends on its old value, or it is reinitialized when it should have accumulated.

Everyone downstream then computes against a lie. Early actors withdraw more than they are owed. The protocol becomes short. The last user out cannot be paid.

## Attack surfaces

**Hunt the missing decrement.** For every transfer out, find the variable that should have decreased. If none exists, or if the decrement lives in only one of several exit paths, you have it. Check `withdraw`, `redeem`, `emergencyWithdraw`, `claim`, expiry paths, liquidation paths, and cross-chain variants — the forgotten one is rarely the main path.
> *Users redeeming early will withdraw `Ra` without decreasing the amount locked, which will lead to stolen funds when withdrawing after expiry*
> *Missing Update to `omnichain.totalAvailableLiquidationAmount` in `withdrawUser`*
> *Method refundPlayers doesn't update `_lockedETH` in WinnableTicketManager*

**Hunt the one-sided branch.** Any `if`/`else` where one branch writes an accounting variable and the other does not. Any early `return` that skips a write. Any `try`/`catch` where the failure path leaves state half-updated.
> *Users will steal excess funds from the Vault due to `VaultPoolLib::redeem()` not always decreasing `raBalance` and `paBalance`*

**Hunt write-before-read.** A variable mutated before the calculation that needed its pre-state. Burning shares before computing share value inflates the price for the burner. Transferring before setting a rate distributes at the wrong rate.
> *`burnSharesToWithdrawEarnings` burns before math, causing the share value to increase*
> *`Voter::finalize()` incorrect rewards distribution due to transferring WETH before calling `distributor::setTokensPerInterval()`*

**Hunt the untracked balance.** A token or ETH balance that is real but has no variable representing it, or is represented by `balanceOf(address(this))`. Live balance reads are donatable and shared across users.
> *Total `ETH`, `WETH` and `gameETH` are not tracked which will lead to insolvency*
> *Lost withdrawals due to `ManagedLeveragedVault::openDen()` using all `asset()` balance*
> *Incorrect withdraw queue balance in TVL calculation*

**Hunt the reinitialization.** State that should accumulate but gets overwritten when a user re-enters. Run deposit → withdraw → deposit on every position-holding structure and check whether the second deposit resets something the first established.
> *Borrower deposit, withdraw, deposit will reinit `omniChainData.cdsPoolValue`, getting profit stuck for cds depositors*
> *Cancelling rounds after finalizing will lead to incorrect `globalTokenAllocPerIDORound` tracking*

**Hunt the mismatched pair.** Two amounts that must be equal but are computed differently — burn `newAmount` but redeem `amount`, debit from `msg.sender` but read state from `user`, credit shares from one formula and debit from another.
> *`BasicVault::_redeem()` burns newAmount but redeems amount, allowing attackers to drain the vault*
> *`Borrowing::redeemYields` debits `ABOND` from `msg.sender` but redeems to `user` using `ABOND.State` data from `user`*
> *Mismatch between yield amount deposited in shares calculation and `getAccountYieldBalance()`*

**Hunt the unreturned value.** A function returns the actual amount moved and the caller ignores it, assuming the requested amount. Fee-on-transfer, partial fills, capped withdrawals, and AMM slippage all make requested ≠ actual.
> *Providing liquidity to the AMM does not check the return value of actually provided tokens leading to locked funds*
> *Fee on transfer tokens transfer less tokens than what is stored in the receipt on deposits*
> *`FlashSwapRouter::emptyReserve()` and `emptyReservePartial()` functions return incorrect values*

**Hunt value with no owner.** Fees, dust, residuals, and yields that accrue to no one and can be claimed by anyone — or by nobody, permanently.
> *Protocol fee from Market.sol is locked*
> *Yield from LRTs are forever stuck in the protocol and cannot be withdrawn*
> *In the `unlockProtectedListing()` function, the interest that was supposed to be distributed to LP holders was instead burned*
> *Interest generated by last bond will not go to anyone when liquidating as there is no bond amount to collect it*

## Required closing test

For every lifecycle in the money map, run `[LastOut: <lifecycle>]`: every user withdraws in the worst possible order. If the protocol is short by any amount, trace back to the step that leaked and report *that*, not the failed withdrawal.

## Every finding needs the balance sheet

State the shortfall concretely: after N steps, users can claim X, the contract holds Y, X > Y by Z. No numbers = LEAD.
